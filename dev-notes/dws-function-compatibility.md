# DWS 函数兼容与后台说明

问题：sqlglot 将 PostgreSQL 正则运算符 `~` 解析为 `REGEXP_LIKE`，原有函数白名单
遗漏这一名称；`TO_DATE`、`TO_CHAR`、`STRING_AGG`、填充和统计函数也存在内部名称差异。

改动：增加有官方文档来源的 DWS 只读函数组，在函数校验边界处理 AST 名称映射，
不改写原始 SQL，不改变表权限、查询确认与执行事务。任意匿名函数不参与内部名称映射，
禁止以相似名称绕过检查。函数参数中的嵌套危险调用仍逐一校验。

后台清单从实际 APPROVED_FUNCTIONS / DANGEROUS_FUNCTIONS 生成，携带官方来源，
支持按名称搜索允许、禁止和未收录项。它说明策略允许范围，不声称全量 DWS 语法或真实数据库验收。

验证：`uv run pytest tests/test_dataquery_policy.py tests/test_dataquery_workflow.py -q`。
覆盖四种正则运算符、文本金额转换、日期格式化、聚合和单月差分窗口表达式，
并验证嵌套危险函数、任意模式前缀、未知函数及白名单外表仍被拒绝。

占位符校验改用解析树的参数节点计数，不再将每一个 `%` 当作参数前缀。
`year_month % 100`、括号取模和字符串百分号不计入参数，命名及美元参数仍拒绝。
已用保存的失败 SQL 验证参数数为零；网页无参数执行沿用原始语句。
